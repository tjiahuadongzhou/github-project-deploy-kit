# GitHub 开源项目深度老师式拆解提示词

请深度讲解这个 GitHub 开源项目：

项目地址：
<在这里粘贴 GitHub 地址>

请你按照老师带学生读课本的方式讲解。

我的要求：

1. 我是小白
2. 我刚接触这个领域
3. 英文术语必须翻译成中文
4. 每个重要概念必须举例
5. 每个文件夹都要解释
6. 每个重要 `md` 文档都要解释
7. 不要只总结表面，要解释它为什么这样设计
8. 讲完后告诉我怎么使用、怎么学习、怎么二次开发

请使用：

- `codebase-onboarding` skill = 代码库入门
- `code-tour` skill = 代码导览
- `documentation-lookup` skill = 文档查找
- `code-reviewer` agent = 通用代码审查员
- 如果是 Python 项目，使用 `python-reviewer` agent
- 如果有安装 / 构建内容，必要时使用 `build-error-resolver` agent，但不要直接安装

## 第一阶段：建立项目地图

请先读取项目顶层目录，输出：

```text
项目名/
├── 文件夹 1：中文解释
├── 文件夹 2：中文解释
├── 文件 1：中文解释
└── 文件 2：中文解释
```

每一项都要说明：

- 英文名是什么意思
- 中文翻译是什么
- 小白应该怎么理解
- 它在项目里负责什么

## 第二阶段：逐个文件夹讲解

请按顺序讲解每个重要文件夹。

每个文件夹按这个格式：

### 文件夹名：英文名 + 中文翻译

例如：

### `agents/` = Agents，智能体 / 代理目录

请解释：

1. 这个文件夹是干嘛的
2. 为什么项目需要它
3. 里面通常放什么
4. 小白怎么理解
5. 举一个生活例子
6. 这个文件夹和其他文件夹有什么关系
7. 我学习时应该怎么看它

如果某个文件夹不重要，请标注：
“这个文件夹初学者可以先跳过”。

## 第三阶段：逐个重要文件讲解

重点讲解：

- `README.md`
- `README.zh-CN.md`
- `CLAUDE.md`
- `AGENTS.md`
- `RULES.md`
- `SECURITY.md`
- `package.json`
- `pyproject.toml`
- `pubspec.yaml`
- `Cargo.toml`
- `go.mod`
- `install.sh`
- `install.ps1`
- `docker-compose.yml`
- `Dockerfile`
- `.env.example`
- `docs` 里的重要 `md` 文件

每个文件按这个格式讲：

### 文件名：英文名 + 中文翻译

请解释：

1. 这个文件是干嘛的
2. 小白怎么理解它
3. 它里面主要写了什么
4. 它对部署有什么影响
5. 它对二次开发有什么影响
6. 我需要重点看哪几部分
7. 可以先跳过哪几部分

## 第四阶段：README / 文档内容拆解

请把 `README` 和重要文档拆成“课程”。

格式：

### 第一课：项目是什么？

解释：

- 原文大概说了什么
- 中文翻译
- 小白理解
- 举例说明

### 第二课：怎么安装？

解释：

- 每条命令是什么意思
- 为什么要运行这条命令
- macOS / Windows / Linux 是否不同
- 国内网络是否需要镜像
- 哪些命令有风险

### 第三课：怎么使用？

解释：

- 最小可运行方式
- 常用命令
- 示例输入输出
- 新手最容易错在哪里

### 第四课：怎么二次开发？

解释：

- 从哪里开始改
- 哪些文件最重要
- 哪些地方不要乱改
- 如何验证改动

## 第五阶段：英文术语词典

请把这个项目里出现的重要英文词整理成表格：

| 英文 | 中文翻译 | 小白理解 | 项目里的作用 |
|---|---|---|---|

要求：

- 不要漏掉核心术语
- 不要只翻译字面意思
- 每个词都要结合项目解释

## 第六阶段：使用方式讲解

请告诉我：

1. 最小使用方式
2. 标准使用方式
3. 高级使用方式
4. 如果我要部署，应该怎么做
5. 如果我要二次开发，应该先改哪里
6. 如果我要学习源码，应该按什么顺序读

## 第七阶段：学习路线

请给我一份学习计划：

### 第 1 天：只看什么
### 第 2 天：动手运行什么
### 第 3 天：改一个小功能
### 第 4 天：理解核心模块
### 第 5 天：尝试二次开发

## 第八阶段：总结

最后输出：

1. 这个项目一句话总结
2. 它最重要的 3 个功能
3. 它最重要的 3 个文件夹
4. 它最重要的 3 个文档
5. 初学者最应该先看什么
6. 初学者最容易误解什么
7. 我应该如何把它用到自己的项目里

## 讲解风格要求

- 全部用中文
- 每个英文关键词后面加中文解释
- 把我当小白
- 多举例
- 多用生活类比
- 不要堆术语
- 不要一次跳太深
- 讲清楚“为什么这样设计”
- 讲清楚“我什么时候需要用它”
- 讲清楚“我不需要管哪些内容”
- 如果项目太大，请先讲顶层结构，再分批深入
- 如果信息不够，请告诉我需要继续打开哪些文件
