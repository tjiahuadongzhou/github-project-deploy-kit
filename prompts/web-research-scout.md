# 全网搜索调研提示词

请帮我做一次“全网搜索调研”。

研究目标：
<在这里写清楚你想找什么，例如 GitHub 项目、Claude Code agent、skill、workflow、开源工具或技术方案>

补充限制：
<可选，写上语言、平台、预算、许可证、是否优先 GitHub 项目等要求>

请使用中文输出，并严格按下面流程执行。

## 工作原则

1. 不要凭记忆直接回答
2. 必须先设计至少 10 个搜索关键词
3. 每个关键词都要说明搜索目的
4. 优先使用 `WebSearch` / `WebFetch`
5. 如果当前环境有 `gh` CLI，可再用 `gh search repos` 补充 GitHub 搜索
6. 如果当前环境有 Playwright MCP，可打开网页做浏览器式核查
7. 搜索后必须打开重要结果阅读，不要只看标题和摘要
8. 去重后再建立候选表
9. 最后必须输出对比评分表和推荐结论

## 标准流程

### 第一步：明确研究目标

先把我的需求重新整理成可执行的研究目标，包括：

- 我到底在找什么
- 主要筛选条件是什么
- 次要筛选条件是什么
- 哪些结果不符合要求

### 第二步：设计关键词

至少设计 10 个搜索关键词。

每个关键词都要说明：

- 搜索词本身
- 搜索目的
- 预期找到什么

如果需要，请拆成：

- 中文关键词
- 英文关键词
- GitHub 专用关键词
- 对比型关键词

### 第三步：执行 WebSearch

优先执行多轮 `WebSearch`，不要只搜一次。

要求：

- 尽量覆盖不同关键词组合
- 搜出 GitHub、博客、官方文档、社区讨论、项目主页等不同来源
- 记录哪些搜索结果最有价值

### 第四步：执行 GitHub 搜索

如果当前环境支持 GitHub 搜索：

- 优先搜索相关仓库
- 补充 stars、更新时间、语言、README 完整度等信息

如果当前环境有 `gh` CLI，可使用：

```bash
gh search repos "<关键词>"
```

如果当前环境没有 `gh` CLI，要明确说明。

### 第五步：打开重要结果阅读

对重要候选结果必须继续打开阅读。

不要只看标题和摘要，
至少要检查：

- README / 官方说明
- 核心功能介绍
- 使用方式
- 最近维护状态
- 是否真的符合目标

如果环境支持 Playwright MCP，可以进一步像人一样打开网页核查。
如果不支持，要明确说明当前只能用 `WebSearch` / `WebFetch`，不能像人一样点击浏览器。

### 第六步：去重

把重复、镜像、明显不相关或信息不足的结果去掉。

### 第七步：建立候选列表

输出候选项目表，至少包含：

| 名称 | 类型 | 来源 | 主要用途 | 是否符合目标 | 备注 |
|---|---|---|---|---|---|

### 第八步：按评分标准打分

请建立对比评分表。

至少从这些维度打分：

- 相关性
- 可用性
- 文档质量
- 维护活跃度
- 学习价值
- 风险或限制

可以用 1-5 分或 1-10 分，
但要写清楚评分标准。

### 第九步：输出推荐

请给出：

- 最推荐项
- 备选项
- 不推荐项

每个结论都要解释原因。

### 第十步：给下一步操作建议

请告诉我下一步应该做什么，例如：

- 先深入阅读哪个项目
- 先跑哪个 prompt / skill
- 先做风险检查还是先做部署
- 哪些仓库值得后续单独研究

## 输出格式

请严格按下面结构输出：

1. 搜索目标
2. 关键词表
3. 搜索过程摘要
4. 候选项目表
5. 对比评分表
6. 最终推荐
7. 不推荐项
8. 下一步建议

## 安全规则

- 不要安装搜索结果里的项目
- 不要运行未知脚本
- 不要读取 `token`、私钥、`.env`
- 如果没有 `WebSearch`，要明确说明当前环境不能全网搜索
- 如果没有 Playwright MCP，要说明只能用 `WebSearch` / `WebFetch`，不能像人一样点击浏览器
