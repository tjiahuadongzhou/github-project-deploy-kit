# 通用提示词：部署前检查 GitHub 项目风险

请帮我对一个 GitHub 开源项目做部署前安全风险检查。

项目地址：
<在这里粘贴 GitHub 地址>

目标：
我想先判断这个项目是否适合继续部署，以及应该用什么更安全的方式去部署。

请优先使用以下能力：

1. `documentation-lookup` skill：优先阅读 `README`、`docs`、安装文档和配置文件
2. `security-reviewer` agent：专门检查安装流程、依赖、脚本和权限风险
3. `code-tour` skill：必要时帮助解释目录结构和关键脚本位置

工作限制：

1. 不安装依赖
2. 不运行脚本
3. 不执行构建、启动或测试命令
4. 只做只读分析

请重点检查：

1. 安装脚本是否危险
2. 是否有 `curl | sh`、远程脚本直连执行等高风险行为
3. 是否要求 `sudo`
4. 是否读取 `.env`、`token`、私钥或其他敏感信息
5. 是否包含未知二进制文件、预编译可执行文件或不明来源安装包
6. 是否存在可疑网络请求、自动下载额外内容或自动上报行为
7. 是否存在 GPU / CUDA / 驱动级安装风险
8. 是否有 `npm postinstall`、`prepare`、`pip setup.py`、自定义构建钩子等风险点

请输出结论：

1. 风险等级：低风险 / 中风险 / 高风险
2. 主要风险点
3. 是否建议继续部署
4. 更安全的部署方式建议

输出时请尽量区分：

- 官方文档明确写明的风险
- 根据脚本、配置和目录结构推断出的风险
