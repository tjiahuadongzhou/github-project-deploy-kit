# repo-risk-check

## 用途

当用户还没决定是否要部署某个 GitHub 项目，
想先做安全和风险检查时，
使用这个 skill。

## 基本原则

1. 只读分析
2. 不安装依赖
3. 不运行脚本
4. 不执行构建、启动或测试命令
5. 不修改原项目源码

## 推荐配合

- `documentation-lookup`
- `security-reviewer`
- `code-tour`

## 检查重点

1. 安装脚本是否危险
2. 是否有 `curl | sh`、远程脚本直连执行等高风险行为
3. 是否要求 `sudo`
4. 是否读取 `.env`、`token`、私钥或其他敏感信息
5. 是否包含未知二进制文件、预编译可执行文件或不明来源安装包
6. 是否存在可疑网络请求、自动下载额外内容或自动上报行为
7. 是否存在 GPU / CUDA / 驱动级安装风险
8. 是否有 `npm postinstall`、`prepare`、`pip setup.py`、
   自定义构建钩子等风险点

## 输出结果

请输出：

1. 风险等级：低风险 / 中风险 / 高风险
2. 主要风险点
3. 是否建议继续部署
4. 更安全的部署方式建议

并区分：

- 官方文档明确写明的风险
- 根据脚本、配置和目录结构推断出的风险
