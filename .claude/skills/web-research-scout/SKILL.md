# web-research-scout

## 用途

当用户想做“全网搜索调研”时使用这个 skill。

适用场景包括：

- 搜索 GitHub 项目
- 搜索 Claude Code agent / skill / workflow
- 搜索开源工具
- 搜索技术方案
- 搜索不同实现路线并做对比推荐

## 工作原则

1. 用中文输出
2. 不要凭记忆直接回答
3. 必须先设计至少 10 个搜索关键词
4. 每个关键词都要说明搜索目的
5. 优先使用 `WebSearch` / `WebFetch`
6. 如果有 `gh` CLI，可用 `gh search repos` 补充 GitHub 搜索
7. 如果有 Playwright MCP，可以做浏览器式核查
8. 搜索后必须打开重要结果阅读
9. 不要只看标题和摘要
10. 去重后再建立候选表
11. 最后输出对比评分表和推荐结论

## 标准流程

### 1. 明确研究目标

先把用户需求整理成清晰的研究目标：

- 到底在找什么
- 主要筛选条件
- 次要筛选条件
- 明确排除条件

### 2. 设计关键词

至少给出 10 个搜索关键词。

每个关键词都要说明：

- 搜索词
- 搜索目的
- 预期找到什么

必要时拆成：

- 中文关键词
- 英文关键词
- GitHub 专用关键词
- 对比型关键词

### 3. 执行 WebSearch

进行多轮 `WebSearch`：

- 不只搜一次
- 覆盖不同关键词组合
- 同时关注 GitHub、官方文档、博客、社区讨论和项目主页

### 4. 执行 GitHub 搜索

如果当前环境支持 GitHub 搜索：

- 补充搜索相关仓库
- 关注 stars、更新时间、语言、README 完整度

如果有 `gh` CLI，可使用：

```bash
gh search repos "<关键词>"
```

如果没有 `gh` CLI，要明确说明。

### 5. 打开重要结果阅读

对重要候选项必须继续打开阅读。

至少要检查：

- README / 官方说明
- 核心功能
- 使用方式
- 最近维护状态
- 是否真正符合研究目标

如果环境有 Playwright MCP，可以进一步做浏览器式核查。
如果没有，要明确说明当前只能使用 `WebSearch` / `WebFetch`。

### 6. 去重

去掉：

- 重复结果
- 镜像仓库
- 明显不相关结果
- 信息不足且无法验证的结果

### 7. 建立候选列表

输出候选项目表，至少包含：

| 名称 | 类型 | 来源 | 主要用途 | 是否符合目标 | 备注 |
|---|---|---|---|---|---|

### 8. 按评分标准打分

至少从下面维度评分：

- 相关性
- 可用性
- 文档质量
- 维护活跃度
- 学习价值
- 风险或限制

要写清楚评分标准。

### 9. 输出推荐

给出：

- 最推荐项
- 备选项
- 不推荐项

每个结论都要写原因。

### 10. 给下一步操作建议

告诉用户下一步适合做什么，例如：

- 继续深入阅读哪个仓库
- 先做风险检查还是先做部署
- 值得继续追踪哪些项目

## 输出格式

请按下面结构输出：

1. 搜索目标
2. 关键词表
3. 搜索过程摘要
4. 候选项目表
5. 对比评分表
6. 最终推荐
7. 不推荐项
8. 下一步建议

## 安全规则

- 不要安装搜索结果里的项目
- 不要运行未知脚本
- 不要读取 `token`、私钥、`.env`
- 如果没有 `WebSearch`，要明确说明当前环境不能全网搜索
- 如果没有 Playwright MCP，要说明只能用 `WebSearch` / `WebFetch`，不能像人一样点击浏览器
