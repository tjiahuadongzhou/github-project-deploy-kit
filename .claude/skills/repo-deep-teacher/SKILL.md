# repo-deep-teacher

## 用途

当用户已经知道项目大概是做什么的，
想进一步按“老师带学生读课本”的方式深挖项目时，
使用这个 skill。

## 基本原则

1. 只读分析
2. 不要默认安装依赖
3. 不要默认运行项目
4. 不要修改被分析的原始 GitHub 项目源码
5. 英文术语必须翻译成中文
6. 重要概念必须给例子

## 推荐配合

- `codebase-onboarding`
- `code-tour`
- `documentation-lookup`
- `code-reviewer`
- 如果是 Python 项目，可额外使用 `python-reviewer`
- 如果涉及安装 / 构建说明，可参考 `build-error-resolver` 的思路解释潜在问题，
  但不要直接安装

## 讲解任务

### 第一阶段：建立项目地图

先读取项目顶层目录，输出：

```text
项目名/
├── 文件夹 1：中文解释
├── 文件夹 2：中文解释
├── 文件 1：中文解释
└── 文件 2：中文解释
```

每一项都要说明：

- 英文名是什么意思
- 中文翻译是什么
- 小白应该怎么理解
- 它在项目里负责什么

### 第二阶段：逐个文件夹讲解

对每个重要文件夹说明：

1. 这个文件夹是干嘛的
2. 为什么项目需要它
3. 里面通常放什么
4. 小白怎么理解
5. 举一个生活例子
6. 和其他文件夹的关系
7. 学习时应该怎么读

如果某个文件夹不重要，
要明确写：
“这个文件夹初学者可以先跳过”。

### 第三阶段：逐个重要文件讲解

重点关注：

- `README.md`
- `README.zh-CN.md`
- `CLAUDE.md`
- `AGENTS.md`
- `RULES.md`
- `SECURITY.md`
- `package.json`
- `pyproject.toml`
- `pubspec.yaml`
- `Cargo.toml`
- `go.mod`
- `install.sh`
- `install.ps1`
- `docker-compose.yml`
- `Dockerfile`
- `.env.example`
- `docs` 中的重要 Markdown 文档

每个文件都要解释：

1. 这个文件是干嘛的
2. 小白怎么理解它
3. 它里面主要写了什么
4. 它对部署有什么影响
5. 它对二次开发有什么影响
6. 应该重点看哪几部分
7. 哪些部分可以先跳过

### 第四阶段：README / 文档内容拆课

把 `README` 和重要文档拆成课程来讲：

- 第一课：项目是什么
- 第二课：怎么安装
- 第三课：怎么使用
- 第四课：怎么二次开发

每课都要说明：

- 原文大概在说什么
- 中文翻译
- 小白理解
- 生活类比
- 实际使用时要注意什么

### 第五阶段：英文术语词典

用表格整理：

| 英文 | 中文翻译 | 小白理解 | 项目里的作用 |
|---|---|---|---|

### 第六阶段：使用方式讲解

说明：

1. 最小使用方式
2. 标准使用方式
3. 高级使用方式
4. 如果要部署，应该怎么做
5. 如果要二次开发，先改哪里
6. 如果要学习源码，按什么顺序读

### 第七阶段：学习路线

给出一个 5 天学习计划：

- 第 1 天：只看什么
- 第 2 天：动手运行什么
- 第 3 天：改一个小功能
- 第 4 天：理解核心模块
- 第 5 天：尝试二次开发

### 第八阶段：总结

最后输出：

1. 一句话总结
2. 最重要的 3 个功能
3. 最重要的 3 个文件夹
4. 最重要的 3 个文档
5. 初学者最该先看什么
6. 初学者最容易误解什么
7. 如何把它用到自己的项目里

## 讲解风格

- 全部用中文
- 每个英文关键词后面加中文解释
- 把用户当小白
- 多举例
- 多用生活类比
- 不要堆术语
- 不要一下跳太深
- 讲清楚为什么这样设计
- 讲清楚什么时候需要它
- 讲清楚哪些内容暂时可以不管
