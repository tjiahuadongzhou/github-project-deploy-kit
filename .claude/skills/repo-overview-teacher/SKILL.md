# repo-overview-teacher

## 用途

当你第一次看到一个 GitHub 开源项目，还不想安装、运行或修改它时，使用这个 skill。

它的目标是：

- 先只读分析项目
- 用老师给小白上课的方式讲解
- 把英文术语翻译成中文
- 解释项目为什么值得看
- 给出后续学习顺序

## 使用要求

1. 不要安装依赖
2. 不要运行项目
3. 不要修改任何文件
4. 只阅读 `README`、`docs`、`package.json`、`pyproject.toml`、`pubspec.yaml`、`Cargo.toml`、`go.mod` 等关键文件
5. 如果项目很大，先只读顶层目录和核心说明文件

## 推荐配合

- `codebase-onboarding`：帮助理解项目的总体用途
- `code-tour`：帮助讲解目录结构
- `documentation-lookup`：优先依据文档结论，不要凭记忆猜

## 输出结构

### 1. 一句话总结这个项目

用一句简单的话说明项目到底是干嘛的，不要直接复述 `README`。

### 2. 这个项目解决了什么问题

解释：

- 没有它之前，用户会遇到什么麻烦
- 它帮用户省了什么时间
- 它更偏向开发、部署、设计、AI 工具还是其他领域

### 3. 这个项目适合谁

分开说明：

- 新手是否适合
- 开发者是否适合
- 设计师是否适合
- 公司团队是否适合
- 个人学习是否适合

### 4. 这个项目为什么值得看

说明：

- 亮点是什么
- 和普通项目的不同点
- 是否适合借鉴
- 是否适合直接使用

### 5. 宏观架构图

用文字画一个项目地图，例如：

```text
项目名/
├── 目录 A：中文解释
├── 目录 B：中文解释
├── 文件 A：中文解释
└── 文件 B：中文解释
```

### 6. 重要英文词翻译

用表格整理：

| 英文 | 中文 | 小白理解 |
|---|---|---|

要求：

- 每个英文词都有中文翻译
- 每个词都有小白解释
- 不只翻译字面意思

### 7. 我应该怎么学习这个项目

给出顺序：

1. 先看什么
2. 再看什么
3. 动手做什么
4. 如何部署
5. 如何二次开发

### 8. 这个项目对我有什么用

说明：

- 我可以直接用它做什么
- 我可以借鉴什么
- 我不应该盲目照搬什么

## 讲解风格

- 全部用中文
- 把用户当成小白
- 不默认用户懂专业术语
- 每个重要英文词后面加中文解释
- 多用生活类比
- 先宏观，再细节
- 不确定的结论要明确说明不确定
